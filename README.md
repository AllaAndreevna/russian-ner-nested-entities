# Извлечение именованных сущностей из русских новостей (NEREL): CRF и компактный трансформер под жёсткие ограничения

Учебный практикум (ИСП РАН), осень 2026. Задача: находить в русскоязычных новостных текстах именованные сущности
29 типов (PERSON, ORGANIZATION, PROFESSION, EVENT, DATE и др.), включая **вложенные** сущности, и возвращать их
границы и тип. Решение сдаётся в проверяющую систему с жёсткими ограничениями, поэтому проект - это не только
«обучить модель», но и инженерная работа в рамках бюджета по размеру и времени.

**Итог:** лучшее решение - три CRF-слоя для вложенных сущностей, **macro-F1 0,5645** на закрытом тесте
(рост с 0,465 у первой версии). Компактный трансформер (rubert-tiny2 с урезанным словарём) на тесте дошёл до 0,5346
и пока уступает CRF; разбор причин и план улучшений ниже.

## Постановка и ограничения

| | |
|---|---|
| Данные | корпус NEREL v1.1 (русские новости, 29 типов сущностей, много вложенных) |
| Метрика | среднее по типам micro-F1 (macro по типам), совпадение границ и типа точное |
| Размер решения | архив ≤ 16 МБ |
| Время | ≤ 30 минут на тест, 8 CPU, 16 ГБ RAM, **без интернета** |
| Состав | `solution.py` с классом `Solution`, описание метода, код обучения и инструкция воспроизведения |
| Правила | тестовая часть корпуса не используется для обучения и подбора; неделя - не более 7 отправок |

Так как метрика усредняется по типам, редкие типы (LAW, CRIME, RELIGION, FAMILY, DISTRICT...) влияют на итог так же,
как частые (PERSON, DATE). Это определило многие решения ниже.

## Результаты на закрытом тесте (проверяющая система)

| # | Решение | Macro-F1 | Precision | Recall |
|---|---|---|---|---|
| 1 | CRF, один слой (плоская BIO-разметка), несколько итераций | 0,445-0,465 (лучшая 0,4646) | 0,600 | 0,397 |
| 2 | CRF, **3 слоя вложенности** (обучение на train) | 0,5469 | 0,631 | 0,492 |
| 3 | то же, обучение на train+dev | **0,5645** | 0,659 | 0,509 |
| 4 | rubert-tiny2, словарь 10 тыс., 9 эпох | 0,4956 | 0,557 | 0,484 |
| 5 | rubert-tiny2, 20 эпох | 0,5117 | 0,550 | 0,508 |
| 6 | rubert-tiny2, 22 эпохи, lr 3e-4, batch 16, словарь 12 тыс., train+dev | 0,5346 | 0,585 | 0,518 |

Локальная валидация (dev, без обучения на нём) хорошо согласуется с тестом: CRF со слоями дал 0,560 на dev и 0,547 на
тесте, так что dev был надёжным ориентиром для экспериментов. Время предсказания на проверяющей системе - 1-2 секунды.

## Что было сделано и почему

### 1. Базовая модель и анализ потолка
Первая версия - линейная цепь CRF (`sklearn-crfsuite`) с ручными признаками (слово, префиксы/суффиксы, форма слова,
регистр, соседи в окне ±2) на плоской BIO-разметке. Результат: 0,469 на dev.

Прежде чем улучшать модель, я посчитала **потолок самой постановки**: если разметить dev «идеально», но в плоском BIO,
macro-F1 всего **0,854**. Причина - вложенные сущности (например, «Россия» внутри «Правительство России»):
плоская разметка теряет их по построению. Это показало, что ≈0,15 качества теряется ещё до модели.

### 2. Слои вложенности
Сущности сортируются по длине и жадно раскладываются по трём слоям так, чтобы внутри слоя спаны не пересекались
(внешние → вложенные → вложенные во вложенные; в train 29 709 / 6 507 / 1 019 сущностей по слоям). На каждый слой
обучается отдельный CRF (параллельно), предсказания объединяются. Потолок разметки вырос с 0,854 до **0,978**.
Эффект на тесте: **+0,08** macro-F1 (0,465 → 0,547). Дообучение на train+dev добавило ещё +0,018.

### 3. Диагностика ошибок и эксперименты с декодированием
Во всех таблицах precision заметно выше recall, то есть модель консервативна. Я проверила смещённое декодирование
(выбор тега по маргинальным вероятностям с порогом на класс `O`): на dev оно не помогло (0,560 → 0,556 и ниже),
поэтому в решение не вошло. Этот негативный результат тоже зафиксирован, чтобы не возвращаться к идее.

### 4. Компактный трансформер под лимит 16 МБ
Чтобы поднять качество на редких типах, я дообучила предобученный `cointegrated/rubert-tiny2` (3 слоя, hidden 312).
Основная инженерная проблема - размер: словарь модели (83 828 токенов) занимает почти весь вес. Решение:
- словарь обрезан до специальных токенов, коротких кусков (≤ 2 символов) и самых частых токенов обучающих текстов
  (≈12 тыс.), остальные превращаются в `[UNK]`; позиционные эмбеддинги обрезаны до 512;
- веса хранятся в fp16: **6,4 млн параметров, ≈12 МБ** (архив около 12 МБ при лимите 16);
- вложенные сущности - тем же приёмом: общий энкодер и три классификационные «головы», по одной на слой;
- инференс на чистом PyTorch с ограничением потоков, 3 секунды на 89 текстов dev;
- подбор числа эпох, learning rate и размера словаря - на dev в Google Colab.

### 5. Анализ неудачи трансформера
На dev (без обучения на нём) трансформер вышел на плато около 0,52 после ~10 эпох, хотя лосс на обучении продолжал
падать, то есть дело не в недообучении, а в обобщении. По типам он проигрывает CRF почти везде, особенно на PERSON
(F1 0,71 против 0,85), то есть на именах - редких словах.

Гипотезы (пока **не проверены экспериментально**):
1. Токенизатор модели приводит текст к нижнему регистру и теряет заглавную букву - сильный признак имени собственного,
   который в CRF задан явно.
2. Обрезка словаря по частоте превращает в `[UNK]` как раз редкие токены (имена, названия) и обнуляет пользу
   предобучения на ненаблюдавшихся словах.

## Инженерные уроки
- Метрика и потолок постановки считаются **до** выбора модели: это сразу показало, что главный рычаг - вложенность.
- Каждое решение сверялось на dev по формуле метрики из условия (macro по типам, строгое совпадение границ); на тест
  отправлялись только проверенные архивы.
- Скрипт `check_submission.py` распаковывает архив во временную папку и запускает его так, как это делает проверяющая
  система (проверка структуры, импорта, формата ответа и времени): он поймал бы ошибки упаковки до отправки.
- Практические грабли: `crfsuite` на Windows не сохраняет модель в папку с кириллицей в пути (молча не пишет файл);
  новая загрузка Hugging Face через Xet может быть недоступна в корпоративной сети; смещения символов ломаются, если
  читать текст без `newline=""`.

## Что дальше
- Добавить в трансформер отдельный эмбеддинг регистра слова и проверить гипотезу 1.
- Оставить весь нужный словарь, но хранить эмбеддинги в сжатом виде (низкоранговое разложение/int8), проверить гипотезу 2.
- Ансамбль CRF + трансформер (сейчас не помещается в 16 МБ; нужна квантизация и более агрессивная регуляризация CRF).
- Сэмплирование/взвешивание редких типов под macro-метрику.

## Структура репозитория
```
solution.py            CRF-решение (класс Solution, признаки, декодирование BIO)
train.py               чтение NEREL, слои вложенности, обучение CRF, метрика, валидация на dev
solution_bert.py       решение на rubert-tiny2 (обрезанный словарь, слои вложенности)
bert_train.py          дообучение трансформера, обрезка словаря, сохранение артефактов
check_submission.py    локальная проверка архива "как у проверяющей системы"
make_bert_zip.py       сборка архива для отправки (трансформер)
docs/                  описания методов, сдававшиеся вместе с решениями, и инструкция воспроизведения
requirements.txt
```
Данные (NEREL), веса моделей и архивы в репозиторий не входят.

## Воспроизведение
```bash
pip install -r requirements.txt
# Данные: скачать NEREL v1.1 ([https://github.com/nerel-ds/NEREL](https://github.com/nerel-ds/NEREL/tree/master/NEREL-v1.1)), положить папки train и dev
# (файлы *.txt и *.ann) в data/train и data/dev. Папку test для обучения не использовать.

# CRF: подбор на dev, затем финальная модель на train+dev
python train.py --data-dir data
python train.py --data-dir data --train-on-dev

# Трансформер (нужен интернет один раз, чтобы скачать модель; GPU ускоряет обучение; параметры лучшего запуска)
python bert_train.py --data-dir data --train-on-dev --epochs 22 --lr 3e-4 --batch-size 16 --max-vocab 12000

# Сборка архива и локальная проверка
python make_bert_zip.py
python check_submission.py submission_bert.zip data/dev
```
Для CRF-архива: `python -m zipfile -c submission.zip solution.py model_0.crfsuite model_1.crfsuite model_2.crfsuite description.txt train.py`.
Путь к проекту лучше задавать латиницей.
